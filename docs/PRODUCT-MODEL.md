# 产品模型

## 1. 项目定位

正式名称：**AdvisorOps**

中文副标题：**客户经营工作台**

目标不是重做完整券商 CRM，而是解决客户经理日常经营中的三个问题：

1. 信息分散：电话、企微、外部系统、人工备注等来源零散，客户状态难以连续沉淀。
2. 不知道下一步先做什么：需要从大量客户中发现当前最值得跟进的人。
3. 跟进容易断档：已经开始处理的客户，下一步、等待对象、约定时间和历史进展容易遗忘。

产品核心价值：

> 把零散客户信息沉淀成连续经营上下文，再把“值得关注的人”转成“可执行的工作”。

## 2. 首页双区模型

### 2.1 工作区

回答：

> 我已经决定处理哪些客户？现在做到哪一步？

工作区不再按 Priority Score 排名，核心是执行状态。

V1 状态：

- `action_required`：下一步动作在客户经理侧。
- `waiting`：当前正在等待客户、内部资料或约定时间。
- `completed_today`：今天这一次经营动作已经闭环。
- `cancelled`：撤销当前工作项；不修改客户经营状态。

附加字段 `waiting_on` 用于说明在等谁：

- customer
- manager
- internal
- scheduled_time

工作区展示重点：

- 当前进展
- 最近客户反馈
- 下一步动作
- 下一步时间
- 当前责任方
- 最近一次沟通

“今日已完成”默认折叠，避免污染当前执行视线。

进行中的 WorkItem 外层只保留“取消跟进 / 记录进展”。

- **取消跟进**：撤销这次工作项，写入 Activity，但不修改客户阶段、意向、下次联系时间等 Snapshot；若客户仍满足发现规则，可以重新回到发现区。
- **结束本轮跟进**：入口放在“记录进展”内部。没有新的沟通内容时可以直接结束；有真实沟通时先记录，再决定“记录后结束本轮”或“记录后继续等待”。结束会将本轮记为 `completed_today` 并写入 Activity，今天不再重复推荐。

### 2.2 发现区

回答：

> 如果我现在有时间，下一位值得新发起动作的客户是谁？

发现区先做“是否存在行动理由”的筛选，再做 Priority 排序。

可进入发现区的主要理由：

- 约定跟进已到期或逾期
- 当前有明确意向，但还没有进入今天的执行流程
- 出现新的客户行为信号
- 长期未有效联系，存在服务维护需要
- 新增人工确认的经营线索

以下情况默认不进入发现区：

- 已经在工作区
- 今天已经完成本轮处理
- 最近刚有效沟通且没有新信号、没有新的到期约定
- 明确处于冷静期
- 已约定未来时间且当前尚未到期

## 3. 客户关系状态与工作状态分离

### Relationship Stage

描述客户关系当前阶段：

- `new`
- `contacted`
- `interested`
- `considering`
- `rejected`
- `dormant`

### Intent Level

描述当前意向：

- `unknown`
- `low`
- `medium`
- `high`

### Follow-up State

由当前时间和计划时间动态推导：

- `none`
- `scheduled`
- `due`
- `overdue`
- `cooldown`

### Work State

描述“这件事今天是否已经进入执行”：

- `suggested`
- `action_required`
- `waiting`
- `completed_today`
- `cancelled`

一个客户可以同时是：

> considering + high intent + overdue

但如果他已经进入工作区，就不再同时出现在发现区。

## 4. 客户全景画像

客户经营不能只依赖年龄、资产、风险等级和意向。V1.1 将客户画像拆成两层：

### 已确认画像事实

包括：

- 粗粒度居住区域
- 职业 / 行业 / 单位类型
- 家庭阶段、家庭责任和未来重要安排
- 收入、负债、现金流与流动性偏好
- 投资经验、主要目标、投资期限、信息偏好
- 偏好沟通渠道和联系时间
- 兴趣、主要顾虑、建立信任的因素

### 待验证经营假设

例如“决策偏慢”“重大事项会与家人共同商量”等，只能作为下一次沟通需要验证的假设，必须保存置信度和依据，不作为客户事实。

这些信息进入客户摘要、沟通整理和 AI 咨询上下文，但软画像不直接参与 Priority 打分。

## 4. Priority 的定义

Priority 不是：

- 成交概率
- 客户价值评分
- 自动销售决策
- 是否应该向客户推荐某个产品

它只表示：

> 当前尚未进入工作区的候选客户中，今天谁更值得优先投入时间。

建议维度：

- Follow-up Urgency
- Intent Signal
- Relationship Progress
- Behavior Signal
- Service Value
- Contact Suppression
- Rejection / Cooldown

人工置顶不直接污染分数。排序优先采用：

1. 是否人工置顶
2. Priority Score
3. 跟进紧迫度

## 5. 客户经营判断

客户详情第一层采用 action-first 结构，先回答三件事：

1. **当前状态**：阶段、意向、当前关注和障碍；
2. **下一步行动**：应该推进、等待还是先准备，需要问清哪些问题，以及本次动作的完成标准；
3. **下一次怎么沟通**：建议开场、沟通方式和应避免事项。

资产、经营事实、全景画像和历史记录下沉到第二层，需要时再展开。

判断来源包括：

- 已确认 Customer Snapshot；
- 当前 WorkItem；
- 最近有效 Activity；
- 已确认画像事实；
- 单独标记的待验证经营假设。

经营判断保持 deterministic / read-only，不写回客户权威状态，也不调用外部模型。画像事实不能压过更近的明确沟通事实；例如客户已明确拒绝时，“历史投资目标”不能重新被解释成当前主动需求。

每个判断都保留 Evidence，可追溯到“当前需求 / 当前障碍 / 最近沟通 / 工作项 / 画像 / 待验证假设”等来源。

## 6. 最近联系过的客户如何处理

不使用“最近 3 天联系过 = 固定扣分”这种粗规则。

真正判断：

> 最近联系以后，现在是否仍存在新的可执行动作。

最近已联系且：

- 没有新信息、没有到期约定 → 抑制重复触达
- 约定今天继续 → 正常进入发现区
- 出现新的重要行为信号 → 可以重新进入发现区
- 已经在等待客户反馈 → 留在工作区
- 已完成今天动作 → 今日不再进入发现区

因此是“无必要重复触达抑制”，不是“最近联系惩罚”。

## 7. 客户动态

客户动态用于解决外部信息来源零散的问题。

来源可能包括：

- CRM
- 企业微信
- 电话系统
- 外部业务系统
- App / 行为数据
- CSV / Excel 导入
- 客户经理人工记录

V1 不假装已经接入任何真实券商系统。

客户动态分为：

### 自动记录事实

例如：

- 通话发生时间
- 通话对象
- 外部系统明确返回的行为事件
- 已发送/已回复等确定事实

### 需要人工确认的解释

例如：

- 当前意向变化
- 当前沟通阶段变化
- 需求变化
- 异议
- 下一步动作
- 下次联系时间

AI 可以提出 Change Proposal，但解释性字段默认不直接落库。

## 8. 完整经营记录

每一次客户互动必须保留完整历史，不只保存 AI 抽取后的字段。

每条活动记录至少包含：

- 来源系统
- 渠道
- 时间
- 原始内容或原始摘要
- 结构化经营摘要
- 客户反馈
- 需求与障碍
- 当前进展
- 下一步
- 下次联系时间
- AI 提取出的候选变化
- 人工最终确认的变化
- 状态变更前后值

客户当前 Snapshot 是为了快速工作；活动时间线才是复盘依据。

## 9. AI 的职责

项目原则：

> **AI 负责理解，规则负责约束，人负责决策。**

V1 最有价值的 AI 能力：

1. 自然语言沟通记录 → 结构化经营记录
2. 客户历史 → 30 秒经营摘要
3. 从沟通内容中发现潜在需求 / 障碍 / 时间信号
4. 生成客户 30 秒经营摘要
5. 生成脱敏 AI 咨询上下文

V1 的发现区 Next Best Action 文案保持规则驱动，不为每次排序额外调用模型，以减少延迟、费用和不稳定性。

AI 暂不负责：

- 最终 Priority 排序
- 正式适当性判断
- 自动修改权威 KYC / 风险等级 / 账户数据
- 自动向客户发送金融建议
- 自动替客户作投资决策

## 10. AI 咨询上下文

客户详情提供“生成 AI 咨询上下文”。

Demo 中全部为模拟数据，可完整展示。

设计仍按真实生产边界实现：

- 字段白名单
- 默认去姓名、手机号、账号等直接身份信息
- 精确金额可降级为区间
- 最近若干次沟通
- 当前状态
- 当前需求
- 当前障碍
- 已采取措施
- 下一步计划
- 用户希望 AI 帮助的问题
- 生成前预览
- 用户主动复制

真实机构落地时，应改为公司批准的 AI Gateway，而不是默认复制真实客户完整资料到个人外部 AI。

## 11. 非目标

V1 不做：

- 完整 CRM
- 真正券商内部系统接入
- 机器学习转化率模型
- RAG
- Agent 自主执行
- 自动金融产品推荐
- 自动客户触达
- 微服务
- 分布式消息系统

V1 要证明的是：

> 业务信息如何沉淀、如何形成连续经营状态、如何发现下一步工作、如何把动作执行完并再次回流。
